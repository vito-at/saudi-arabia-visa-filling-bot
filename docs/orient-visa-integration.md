# Интеграция сайта Orient Visa и CRM Orient Travel (вариант Б)

> Общий документ для обоих репозиториев: `vito-at/orient-visa` (сайт) и `vito-at/saudi-arabia-visa-filling-bot` (CRM, папка `crm/`).
> Решение владельца (18.10.2026): **визовые специалисты работают только в CRM**. Сайт — витрина и личный кабинет клиента.
> Перед работой над интеграцией прочитайте этот документ; изменения договорённостей вносите сюда в обоих репозиториях.

## Что уже умеет сайт (не дублировать в CRM)

- Каталог 46 стран (≈19 включены) + виза в Узбекистан для иностранцев, у страны — типы виз (срок, кратность, обычная/срочная обработка), цены в сумах (иностранцам — в долларах).
- Заявители из любой страны: доступность виз, сборы и документы зависят от гражданства; при необходимости оператор подтверждает заявку до оплаты.
- Мастер заявки: поездка (даты, число туристов, срочность) → анкета на каждого туриста (латиница, поля задаются в админке сайта по типу визы) → документы по списку требований страны (фото, паспорт… проверка типа файла по содержимому) → контакты → согласие с офертой.
- Оплата: Payme, Click, депозит агентства; чек PDF; возвраты.
- Личный кабинет клиента: статус, история, переписка, исправления без повторной оплаты, скачивание визы / подтверждения отказа; уведомления email / Telegram / SMS.
- Анкеты шифруются (AES-256-GCM), файлы — в приватном S3, доступ по подписанным ссылкам, просмотры ПД пишутся в журнал.

Панель оператора на сайте (`/ops`) при включённой интеграции **не используется визовиками** (остаётся для админа как резерв).

## Поток

```
Клиент на сайте: страна → тип визы → срочность → анкета → документы → оплата
        │  (статус PAID)
        ▼
[сайт → CRM] заявка: лид «Сайт» + визовая заявка (LeadService VISA, source WEBSITE, handedAt = сразу)
        │
Визовик в CRM: берёт заявку, смотрит анкету и документы, подаёт на портал, меняет статусы
        │  (каждая смена статуса)
        ▼
[CRM → сайт] событие: статус / запрос исправлений / файл визы / подтверждение отказа / сообщение клиенту
        ▼
Сайт: меняет статус заявки в кабинете клиента и отправляет ему уведомление
```

## 1. Сайт → CRM: создание заявки после оплаты

`POST {CRM_API_URL}/api/public/visa-application`, `Authorization: Bearer {CRM_API_KEY}` — существующий маршрут CRM, **расширяется** новыми необязательными полями (старые поля и ответы не меняются):

```jsonc
{
  "name": "VALIYEV ALI", // контактное лицо
  "phone": "+998901234567",
  "country": "Индия", // по-русски, как в CRM
  "email": "ali@example.uz",
  "travelers": 2,
  "travelFrom": "2027-03-01",
  "travelTo": "2027-03-10",
  "comment": "…",
  // новое ↓
  "externalId": "cmvbq9czd00797dfuo3e0c5oa", // id заявки на сайте — КЛЮЧ ИДЕМПОТЕНТНОСТИ
  "externalNumber": "OV-000123",
  "externalUrl": "https://orientvisa.uz/ops/applications/…",
  "visaType": "Туристическая e-Visa, 30 дней",
  "urgent": false,
  "paidAmount": 467000, // сум (целое)
  "nationality": "IN", // гражданство заявителя (ISO2); с 21.10.2026 сайт принимает заявки от граждан любой страны
  "agency": null, // { "name", "inn" } — если заявку подало агентство-партнёр
}
```

- **Идемпотентность:** повторный запрос с тем же `externalId` не создаёт дубль, а возвращает `200 {"ok": true, "id": "<тот же LeadService>"}`. Сайт повторяет отправку при сетевой ошибке и 5xx (outbox + воркер, до успеха), поэтому без этого будут дубли.
- Ответ `201 {"ok": true, "id": "<LeadService.id>"}` — сайт сохраняет `id` у себя.
- Сайт отправляет запрос **только с сервера** (воркер), ключ — только в окружении.

## 2. CRM ← сайт: анкета и документы (CRM забирает сама)

Паспортные данные и файлы не кладём в тело создания заявки. CRM забирает их отдельным запросом к сайту — при получении заявки и повторно после исправлений:

`GET {SITE_URL}/api/integration/applications/{externalId}`, `Authorization: Bearer {SITE_INTEGRATION_KEY}`

```jsonc
{
  "id": "…", "number": "OV-000123", "status": "PAID",
  "country": { "iso2": "IN", "name": "Индия" }, "visaType": "…", "urgent": false,
  "nationality": "UZ",
  "travelDate": "2027-03-01", "returnDate": null,
  "contact": { "name": "…", "phone": "+998…", "email": "…", "telegram": "…" },
  "travelers": [
    {
      "id": "…", "position": 1, "name": "VALIYEV ALI",
      "fields": [ { "key": "passport_number", "label": "Номер паспорта", "value": "FA1234567" }, … ],
      "documents": [
        { "id": "…", "title": "Фотография", "mime": "image/jpeg", "size": 123456,
          "status": "UPLOADED", "url": "https://…подписанная ссылка, 10 минут…" }
      ]
    }
  ],
  "updatedAt": "…"
}
```

- CRM **скачивает файлы сразу** и хранит у себя (ссылки живут 10 минут).
- Каждый запрос пишется в журнал сайта как просмотр ПД (`pd.export`).

## 3. CRM → сайт: события по заявке

`POST {SITE_URL}/api/integration/crm-events`, тело JSON, подпись: заголовок `X-Signature: sha256=<hex HMAC-SHA256(тело, CRM_WEBHOOK_SECRET)>`, `X-Event-Id: <уникальный id>` (сайт игнорирует повторы).

```jsonc
{
  "externalId": "…",
  "serviceId": "…",
  "type": "status",
  "status": "DOCS_REQUESTED",
  "comment": "Перезагрузите фото: светлый фон", // увидит клиент
  "rejectedDocuments": ["<id документа с сайта>"], // для DOCS_REQUESTED, необязательно
  "portalReference": "T123456789", // необязательно
  "file": { "url": "https://crm…/подписанная ссылка", "name": "visa.pdf" }, // для APPROVED / REJECTED
  "proofType": "OFFICIAL",
} // REJECTED: OFFICIAL | EMAIL | SCREENSHOT
```

Также `type: "message"` — `{ "externalId", "type": "message", "text": "…" }` — сообщение визовика клиенту (появится в переписке на сайте).

**Соответствие статусов** (CRM `VisaStatus` → сайт `ApplicationStatus`):

| CRM            | Сайт             | Клиенту                                                                       |
| -------------- | ---------------- | ----------------------------------------------------------------------------- |
| NEW            | PAID             | «Оплачена» (уже стоит)                                                        |
| IN_PROGRESS    | DOCUMENT_REVIEW  | «Документы на проверке»                                                       |
| DOCS_REQUESTED | NEEDS_CORRECTION | комментарий + отклонённые документы, клиент исправляет без оплаты             |
| PAID_WAITING   | SUBMITTED        | «Подана в посольство» (+ номер на портале)                                    |
| APPROVED       | APPROVED         | файл визы — скачивание в кабинете                                             |
| REJECTED       | REJECTED         | подтверждение отказа (официальный документ → письмо → скриншот, как в оферте) |

Когда клиент отправил исправления, сайт повторяет шаг 1 (тот же `externalId`) с `"event": "corrections_submitted"` — CRM возвращает заявку в работу (`IN_PROGRESS`) и заново забирает анкету и документы (шаг 2).

## Переменные окружения

| Где  | Переменная                                               | Назначение                                                                                                                                                  |
| ---- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| сайт | `CRM_API_URL`, `CRM_API_KEY`                             | отправка заявок в CRM (ключ — из CRM «Настройки → Визы и документы»)                                                                                        |
| сайт | `SITE_INTEGRATION_KEY`                                   | ключ, с которым CRM забирает анкету и документы                                                                                                             |
| сайт | `CRM_WEBHOOK_SECRET`                                     | проверка подписи событий от CRM                                                                                                                             |
| CRM  | `SITE_URL`, `SITE_INTEGRATION_KEY`, `CRM_WEBHOOK_SECRET` | те же значения; можно не в окружении, а в CRM «Настройки → Визы и документы → Сайт Orient Visa» (ключи хранятся зашифрованными, настройки важнее окружения) |

## Кто что делает

**Сессия сайта (orient-visa):** отправка после оплаты через outbox с повторами; `GET /api/integration/applications/{id}`; приём событий с проверкой подписи и идемпотентностью; применение статусов, файлов и сообщений к заявке клиента; выключение панели `/ops` для визовиков при включённой интеграции.

**Сессия CRM:** новые поля в `/api/public/visa-application` и идемпотентность по `externalId`; загрузка анкеты и документов с сайта в карточку визовой заявки; отправка событий на сайт при смене статуса, запросе документов, загрузке визы / отказа и сообщении клиенту; повторы при ошибке.

## Как сделано в CRM (19.10.2026)

- **Приём** (`crm/src/app/api/public/visa-application/route.ts`):
  - повтор с тем же `externalId` → `200` с тем же `id`, в том числе при одновременных запросах (они обрабатываются по очереди);
  - на `"event": "corrections_submitted"` заявка переходит в `IN_PROGRESS`, анкета и документы забираются заново, визовику приходит уведомление. Событие `status` на сайт в этом случае **не** отправляется: сайт сам знает об исправлениях.
- **Анкета** хранится в CRM зашифрованной (`LeadService.siteDataEnc`, AES-256-GCM), визовик видит её в карточке заявки.
- **Документы:**
  - скачиваются сразу и сохраняются в CRM с `externalId` документа сайта и именем туриста;
  - уже скачанный документ (тот же `id` на сайте) повторно не загружается;
  - исправленный файл должен прийти с новым `id`.
- **Повторы:**
  - загрузка с сайта при ошибке повторяется воркером раз в минуту с растущей паузой 1, 2, 4… минут, не больше 6 часов, до 30 попыток;
  - в карточке есть кнопка «Обновить с сайта».
- **События на сайт** (`SiteEvent`, воркер раз в минуту):
  - внутри одной заявки уходят строго по порядку: пока не доставлено раннее, следующие ждут;
  - повтор при ошибке с паузой 1, 2, 4… минут, не больше 6 часов, без ограничения числа попыток;
  - `X-Event-Id` — id события, он одинаковый во всех повторах;
  - событие `status` отправляется при смене этапа, при комментарии клиенту (тот же этап) и при новом `portalReference`;
  - `IN_PROGRESS` уходит и тогда, когда визовик нажимает «Взять себе» на новой заявке.
- `comment` уходит, только если визовик оставил отметку «Комментарий увидит клиент» (она включена по умолчанию). Иначе комментарий остаётся внутренним.
- `rejectedDocuments` — `id` документов сайта, которые визовик отметил при запросе исправлений.
- `file.url`:
  - это подписанная ссылка `GET {CRM}/api/public/visa-file/{id}?exp=…&sig=…`, где подпись — HMAC-SHA256 от `{id}.{exp}` с `CRM_WEBHOOK_SECRET`;
  - ссылка **живёт 1 час**, при каждом повторе события создаётся новая;
  - сайт должен скачать файл сразу.
- Для `APPROVED` и `REJECTED` CRM не даёт сменить этап без файла, а для `REJECTED` — ещё и без `proofType`.

## Персональные данные

Паспортные данные будут храниться и в CRM — сервер CRM тоже должен быть в Узбекистане (ЗРУ-547, ст. 27¹), файлы — в закрытом хранилище, доступ к ним — в журнал.

## Как сделано на сайте (21.10.2026)

- **Отправка в CRM:** запись `CrmOutbox` создаётся в той же транзакции, что и переход в `PAID` (любая оплата) или `NEEDS_CORRECTION → DOCUMENT_REVIEW` по действию клиента (`event: corrections_submitted`). Переходы, пришедшие из CRM, обратно не отправляются. Воркер — раз в минуту и сразу после события; по порядку внутри заявки; повтор с паузой 1, 2, 4… минут (до 6 часов) при сетевой ошибке, 401/403, 408/429 и 5xx; 400/413/422 — ошибка данных, повтор только по кнопке администратора. `id` из ответа сохраняется в `Application.crmServiceId`.
- `phone` — в международном формате (`+998…`, у иностранцев — их код страны); `paidAmount` — целые сумы; `externalUrl` — карточка заявки в `/ops` (для администратора).
- **Анкета:** черновики, «ждёт подтверждения», «ждёт оплаты» и отменённые — `404`. Значения полей — для людей: вариант списка по-русски, страна — `XX — название`, да/нет. Документы «на всю группу» отдаются у первого туриста.
- **События:** ответ `200 {"ok": true, "result": "applied" | "duplicate" | "ignored:<причина>"}` — CRM не повторяет. Причины: `not_found`, `unknown_type`, `unknown_status`, `final` (заявка завершена), `transition` (перехода нет, например заявка не оплачена или возвращена), `file_required`, `file_origin` (ссылка не с адреса `CRM_API_URL`), `file_bad_type` / `file_too_large` (PDF/JPG/PNG/WebP до 20 МБ), `empty`. `401` — подпись, `400` — нет `X-Event-Id` или не JSON, `503` — временная ошибка (файл не скачался, статус изменился параллельно), CRM повторяет.
- Если CRM пропустила этапы сайта (например `NEW` → `APPROVED`), сайт проходит промежуточные статусы сам, клиент получает одно уведомление — о последнем. `comment` попадает в уведомление о статусе и в переписку; без смены этапа — только в переписку (с уведомлением). Для `DOCS_REQUESTED` без комментария клиенту пишется стандартный текст.
- `NEW` (→ `PAID`) не применяется: оплату подтверждает только платёжная система сайта.
