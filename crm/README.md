# Orient Travel CRM

CRM для обработки лидов туристического агентства «Orient Travel» (Фергана, Узбекистан).
Лиды автоматически загружаются из форм Meta Lead Ads (Facebook и Instagram), распределяются между менеджерами и проходят по воронке до продажи. По ним строятся отчёты: выручка, прибыль, причины отказов, эффективность рекламы и работа менеджеров.

Интерфейс на русском, узбекском и английском языках. Он работает на компьютере и на телефоне: на телефоне меню открывается кнопкой в верхней панели, лиды показываются карточками с кнопкой звонка, а широкие таблицы отчётов прокручиваются вбок. Даты показываются в формате ДД.ММ.ГГГГ по часовому поясу Asia/Tashkent. Оформление — в фирменном стиле Orient Travel, с переключателем «День / Ночь» внизу бокового меню. Выбор запоминается, а при первом входе берётся тема операционной системы.

**Языки:** русский, узбекский (латиница) и английский. Переключатель RU / UZ / EN находится внизу бокового меню и на странице входа; у каждого сотрудника язык свой. На выбранном языке показываются все экраны, сообщения об ошибках, отчёты и выгрузка в Excel. Стандартные статусы и причины отказа («Новый», «Продано», «Дорого»…) тоже переводятся. Названия, которые компания создала или переименовала сама, показываются как есть. Данные клиентов, комментарии и ответы из рекламных форм не переводятся.

## Возможности

**Загрузка лидов из Meta**
- Лиды со всех лид-форм страницы: `GET /{page_id}/leadgen_forms`, затем `GET /{form_id}/leads` с пагинацией.
- Опрос по расписанию. По умолчанию раз в 5 минут, интервал задаётся в настройках.
- Кнопка «Загрузить сейчас».
- Вебхук `leadgen` для мгновенной доставки. Проверяются `verify_token` и подпись `X-Hub-Signature-256`.
- Загружаются только новые лиды: учитывается время последней синхронизации, дубли по `leadgen_id` отсекаются.
- Разбор `field_data`:
  - имя, телефон и email попадают в карточку;
  - ответы на кастомные вопросы (направление, даты, количество человек и т. д.) сохраняются в JSON и показываются в карточке с подписями вопросов из формы;
  - понимаются вопросы на русском, узбекском и английском языках.
- Телефоны приводятся к формату `+998XXXXXXXXX`. Лид с уже известным номером отмечается как «повторное обращение», привязывается к существующему клиенту и достаётся прежнему менеджеру.
- Журнал синхронизаций. Если токен истёк, вверху каждой страницы появляется красный баннер.
- Ручное создание лида для звонков, Instagram Direct, Telegram и визитов в офис.

**Работа с лидами**
- Таблица лидов:
  - поиск по имени и телефону;
  - фильтры: статус, менеджер, источник, кампания, форма, период;
  - сортировка, пагинация, массовое назначение менеджера.
- Канбан-доска с перетаскиванием карточек. Из меню убрана, потому что менеджеры работают со списком лидов. Страница осталась по адресу `/kanban`, а вернуть пункт меню можно строкой в `src/components/layout/sidebar.tsx`.
- Статусы настраиваются: можно добавлять новые, переименовывать, менять цвет и порядок.
- Перевод в «Отказ» требует выбрать причину. Список причин редактируется в настройках.
- Перевод в «Продано» требует заполнить сделку.
- Карточка лида:
  - кликабельный телефон и ссылки на WhatsApp и Telegram;
  - ответы из формы и данные рекламы;
  - тип услуги, направление, даты поездки, количество туристов;
  - комментарии (свои можно редактировать) и история изменений.
- Задачи и напоминания («перезвонить в 15:00»). Просроченные и сегодняшние задачи видны на дашборде.
- Статус **«Перезвонить»**:
  - при его выборе обязательно указываются дата и время звонка, менеджеру автоматически создаётся задача;
  - за 10 минут до звонка лид появляется в блоке «Скоро звонок» над таблицей лидов с обратным отсчётом в минутах;
  - на любой странице CRM всплывает напоминание, в том числе системное уведомление браузера, если оно разрешено;
  - когда время наступает — пометка «Пора позвонить» и кнопка «+10 мин», чтобы отложить звонок.
- Новые лиды подсвечиваются. Если лид не взят в работу за N минут, он выделяется красным.

**Сделки и деньги**
- Сделка содержит сумму продажи, себестоимость, валюту (UZS или USD), дату оплаты и описание продукта.
- Прибыль считается автоматически: продажа минус себестоимость.
- У клиента может быть несколько сделок. В карточке клиента видны выручка и прибыль за всё время.
- Суммы пересчитываются по курсам Ипак Йули Банка (или по курсам, введённым вручную): выручка по курсу продажи $, себестоимость, реклама и расходы компании по курсу покупки $ (дорогому). Любой отчёт можно смотреть в USD или UZS.

**Отчёты** (фильтр по периоду и менеджеру, выгрузка в Excel)
- Дашборд: лиды, продажи, конверсия, выручка, прибыль, средний чек и сравнение с прошлым периодом.
- Клиенты: количество сделок, выручка и прибыль. Из отчёта можно открыть все сделки клиента.
- Воронка: сколько лидов дошло до каждого статуса.
- Причины отказов: круговая диаграмма и таблица, разбивка по менеджерам и кампаниям.
- Реклама на уровнях «кампания», «группа», «объявление» и «форма»:
  - лиды, продажи, конверсия, выручка и прибыль;
  - если подключён Marketing API: расход, цена лида, цена продажи и ROI.
- Менеджеры: лиды в работе, продажи, конверсия, прибыль, среднее время первой реакции.
- Типы услуг и направления.

## Стек и структура

- **Next.js 15** (App Router, Server Actions) и **TypeScript**.
- **Prisma 6** и **PostgreSQL 16**.
- **Tailwind CSS 4** с компонентами в стиле shadcn/ui (Radix UI), **Recharts** для графиков, **dnd-kit** для канбана, **ExcelJS** для выгрузки.
- **Auth.js (NextAuth v5)**: вход по логину и паролю, пароли хранятся в виде bcrypt-хешей, сессии в JWT.
- **Воркер** на node-cron (отдельный контейнер): опрос Meta, загрузка расходов на рекламу, обновление курса.
- Секреты интеграции (App Secret и токены) хранятся в базе в зашифрованном виде (AES-256-GCM).

```
crm/
├── prisma/
│   ├── schema.prisma        # модели БД
│   ├── migrations/          # миграции
```

## Быстрый старт (локально)

Понадобятся Node.js 22+ и Docker (или установленный PostgreSQL 16).

```bash
cd crm
cp .env.example .env
# в .env сгенерируйте секреты:
#   AUTH_SECRET:     openssl rand -base64 32
#   ENCRYPTION_KEY:  openssl rand -hex 32
# и укажите APP_URL=http://localhost:3000

# 1. База данных в Docker
docker compose up -d db

# 2. Зависимости, миграции, тестовые данные
npm install
npx prisma migrate deploy
npm run db:seed

# 3. Приложение и воркер (в двух терминалах)
npm run dev
npm run worker
```

Откройте http://localhost:3000.

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | из `ADMIN_PASSWORD` в `.env` (по умолчанию `admin123`) | Администратор |
| `dilshod`, `gulnora`, `sardor` | `manager123` | Менеджеры (создаются вместе с демо-данными) |

> Демо-данные: около 100 лидов за последние 90 дней, сделки, отказы с причинами, задачи и расходы на рекламу. Их хватает, чтобы сразу посмотреть все отчёты. Для боевой базы задайте `SEED_DEMO=false`.

### Всё в Docker

```bash
cp .env.example .env    # заполните секреты
docker compose up -d --build
docker compose exec app npm run db:seed
```

Контейнер `app` при старте сам применяет миграции (`prisma migrate deploy`).

## Приложение в Meta for Developers

1. Зайдите на https://developers.facebook.com → **My Apps → Create App**.
2. Тип приложения: **Business** (или сценарий «Other → Business»). Привяжите приложение к бизнес-портфолио (Business Manager), которому принадлежат страница и рекламный кабинет.
3. В приложение добавьте продукты:
   - **Facebook Login for Business** (нужен для получения токена);
   - **Webhooks** (для мгновенной доставки лидов);
   - **Marketing API** (если хотите видеть расходы и ROI).
4. **App Settings → Basic**: скопируйте **App ID** и **App Secret**. Там же укажите Privacy Policy URL (для боевого режима он обязателен).
5. Разрешения, которые нужны CRM:
   - `leads_retrieval`: чтение лидов;
   - `pages_show_list`, `pages_read_engagement`: доступ к странице;
   - `pages_manage_metadata`: подписка страницы на вебхук;
   - `ads_read`: названия кампаний и расходы.

   Пока приложение в режиме **Development**, эти права работают для администраторов и разработчиков приложения. Этого достаточно, если токен получает сотрудник агентства с ролью в приложении. Для режима **Live** нужны *Advanced Access* и проверка бизнеса (Business Verification).
6. Проверьте доступ к лидам: **Meta Business Suite → Настройки компании → Интеграции → Доступ к лидам** (Leads Access). Пользователь, от чьего имени получен токен, и приложение должны иметь доступ к лидам этой страницы.
7. Узнайте **Page ID**: страница Facebook → «Информация» → «Прозрачность страницы», или `GET /me/accounts` в Graph API Explorer.

## Долгосрочный Page Access Token

CRM нужен токен страницы, который не истекает. Есть два способа.

### Способ А: токен системного пользователя (рекомендуется)

Такой токен не зависит от личного аккаунта сотрудника и не сбрасывается при смене пароля.

1. **Business Manager → Настройки компании → Пользователи → Системные пользователи → Добавить**. Роль: *Admin*.
2. Нажмите **Назначить ресурсы** и выдайте системному пользователю страницу (полный доступ), приложение и рекламный кабинет (для расходов).
3. Нажмите **Создать новый токен**. Выберите приложение, срок действия *Никогда* и разрешения `leads_retrieval`, `pages_show_list`, `pages_read_engagement`, `pages_manage_metadata`, `ads_read`.
4. Полученный токен пока **пользовательский**. Получите по нему токен страницы:
   ```
   GET https://graph.facebook.com/v26.0/me/accounts?access_token=<ТОКЕН_СИСТЕМНОГО_ПОЛЬЗОВАТЕЛЯ>
   ```
   В ответе найдите вашу страницу и скопируйте поле `access_token`. Это и есть бессрочный Page Access Token.
5. Сам токен системного пользователя вставьте в поле «Токен Marketing API» в настройках CRM. Он нужен для загрузки расходов.

### Способ Б: через Graph API Explorer

1. Откройте https://developers.facebook.com/tools/explorer. Выберите своё приложение, **User Token** и добавьте разрешения из списка выше. Нажмите **Generate Access Token** и подтвердите доступ к странице.
2. Обменяйте короткий токен (живёт около часа) на долгосрочный (около 60 дней):
   ```
   GET https://graph.facebook.com/v26.0/oauth/access_token
       ?grant_type=fb_exchange_token
       &client_id=<APP_ID>
       &client_secret=<APP_SECRET>
       &fb_exchange_token=<КОРОТКИЙ_ТОКЕН>
   ```
3. По долгосрочному пользовательскому токену получите токен страницы:
   ```
   GET https://graph.facebook.com/v26.0/me/accounts?access_token=<ДОЛГОСРОЧНЫЙ_ТОКЕН>
   ```
   Токен страницы, полученный из долгосрочного пользовательского, **не имеет срока действия**. Он перестанет работать, если сотрудник сменит пароль, потеряет роль на странице или отзовёт доступ приложения. В этом случае CRM покажет красный баннер: получите новый токен и вставьте его в настройках.
4. Проверьте токен в https://developers.facebook.com/tools/debug/accesstoken: должно быть «Expires: Never». Можно проверить и кнопкой «Проверить токен» в CRM.

## Настройка интеграции в CRM

**Настройки → Интеграция с Meta:**

1. Заполните App ID, App Secret, Page ID и Page Access Token. Секреты сохраняются в зашифрованном виде; в интерфейсе видна только маска.
2. Нажмите **Проверить токен**. CRM покажет название страницы, срок действия токена и недостающие разрешения.
3. Включите галочку «Интеграция включена» и сохраните. Воркер начнёт опрашивать Meta с заданным интервалом. При первом запуске загружаются лиды за последние N дней (по умолчанию 30; Meta хранит лиды 90 дней).
4. Кнопка **Загрузить лиды сейчас** запускает синхронизацию немедленно. Такая же кнопка есть на странице «Лиды».
5. Для расходов и статистики рекламы укажите ID рекламного кабинета (`act_…`) и, при необходимости, отдельный токен Marketing API (нужно право `ads_read`). Раз в час CRM загружает по каждому объявлению расход, показы и клики по ссылке. В «Отчёты → По рекламе» видно по кампаниям, группам и объявлениям: расход, показы, клики, CTR, цену клика, лиды, цену лида, продажи, конверсию, выручку, прибыль и ROI. Кампании с расходом, но без лидов, тоже попадают в отчёт.

### Вебхук (мгновенная доставка)

Работает только после деплоя на сервер с HTTPS и публичным доменом.

1. В CRM на вкладке интеграции скопируйте **Callback URL** (`https://ваш-домен/api/webhooks/meta`) и **Verify Token**.
2. В Meta for Developers: **Приложение → Webhooks → Page → Subscribe to this object**. Вставьте Callback URL и Verify Token, нажмите **Verify and Save**. Meta сделает GET-запрос, CRM ответит `hub.challenge`.
3. В списке полей подпишитесь на **leadgen**.
4. В CRM нажмите **Подписать страницу на вебхук**. Это выполнит `POST /{page_id}/subscribed_apps?subscribed_fields=leadgen`.
5. Проверьте работу в **Lead Ads Testing Tool**: https://developers.facebook.com/tools/lead-ads-testing. Тестовый лид должен появиться в CRM через несколько секунд, а в журнале синхронизаций — запись «Вебхук».

Каждый запрос вебхука проверяется по подписи `X-Hub-Signature-256` (HMAC-SHA256 с App Secret). Запросы с неверной подписью отклоняются с кодом 401. Если лид из вебхука по какой-то причине не загрузился, его подхватит плановый опрос.

## Деплой на VPS с HTTPS

Пример для Ubuntu 22.04/24.04. Серверу нужно 1–2 ГБ RAM.

1. **DNS.** Создайте A-запись `crm.ваш-домен.uz`, указывающую на IP сервера.
2. **Docker:**
   ```bash
   curl -fsSL https://get.docker.com | sh
   sudo usermod -aG docker $USER   # перелогиньтесь
   ```
3. **Код и настройки:**
   ```bash
   git clone <репозиторий> orient-crm && cd orient-crm/crm
   cp .env.example .env
   nano .env
   ```
   Обязательно заполните:
   - `POSTGRES_PASSWORD`: надёжный пароль;
   - `AUTH_SECRET`: `openssl rand -base64 32`;
   - `ENCRYPTION_KEY`: `openssl rand -hex 32`;
   - `APP_URL=https://crm.ваш-домен.uz` и `DOMAIN=crm.ваш-домен.uz`;
   - `ADMIN_PASSWORD` и `SEED_DEMO=false`.
4. **Запуск с HTTPS.** Caddy сам получит и будет продлевать сертификат Let's Encrypt:
   ```bash
   docker compose --profile https up -d --build
   docker compose exec app npm run db:seed    # администратор и справочники
   ```
5. **Фаервол.** Откройте только 22, 80 и 443:
   ```bash
   sudo ufw allow OpenSSH && sudo ufw allow 80 && sudo ufw allow 443 && sudo ufw enable
   ```
   PostgreSQL и само приложение слушают только `127.0.0.1` и снаружи недоступны.
6. Откройте `https://crm.ваш-домен.uz`, войдите администратором, смените пароль (Настройки → Пользователи) и настройте интеграцию и вебхук по инструкции выше.

Логи: `docker compose logs -f app worker`.

> Если на сервере уже есть Nginx, вместо Caddy проксируйте `127.0.0.1:3000` и получите сертификат через certbot. Заголовок `Host` должен передаваться, а в `.env` должно стоять `AUTH_TRUST_HOST=true`.

## Курс доллара (Ипак Йули Банк)

**Настройки → Общие → Курс USD → UZS.**

В CRM два курса:

- **курс продажи $** (банк покупает доллары, дешевле): по нему пересчитывается **выручка**;
- **курс покупки $** (банк продаёт доллары, дороже): по нему пересчитываются **себестоимость, реклама и расходы компании**.

Прибыль считается **по минимуму**: выручка пересчитывается по тому курсу, при котором она меньше, а расходы — по тому, при котором они больше (`convertRevenue` / `convertCost` в `src/lib/money.ts`):

| | доллары → сумы | сумы → доллары |
|---|---|---|
| выручка | × курс продажи (меньший) | ÷ курс покупки (больший) |
| себестоимость, реклама, расходы | × курс покупки (больший) | ÷ курс продажи (меньший) |

Курс покупки не может быть ниже курса продажи.

**Продажа и себестоимость в разных валютах.** У сделки две валюты: валюта продажи и валюта себестоимости (`Deal.currency`, `Deal.costCurrency`). Например, продажа в долларах, а туроператору заплатили в сумах. В отчётах каждая сумма пересчитывается из своей валюты по правилам выше. Прибыль отдельной сделки в карточках показывается в валюте продажи: себестоимость пересчитывается по курсу её дня, при котором она больше.

Все сотрудники видят в боковом меню блок **«Курс $ для клиентов»** с курсом покупки $ (дорогим) и калькулятором: вводите сумму в долларах, получаете сумму в сумах, а нажатием её можно скопировать, чтобы отправить клиенту.

- **Ипак Йули Банк (автоматически).** Каждый день в **07:00 по Ташкенту** воркер открывает публичные страницы с курсами (без API): сайт банка, bank.uz, depozit.uz; список задаётся в `IPAK_RATE_URLS`. На странице ищется строка USD с курсами покупки и продажи банка, и сохраняются оба.
- Если обновить курс не получилось, воркер повторяет попытки каждые 30 минут до 12:00. Пока курс не обновлён, все сотрудники видят небольшое уведомление: какой курс сейчас используется и с какой даты. У каждого оно показывается один раз в день.
- **Вручную.** Администратор вводит оба курса сам.
- **«Установить курсы вручную»** работает в любом режиме: курсы сразу применяются ко всем отчётам, а уведомление у сотрудников пропадает. В автоматическом режиме такой курс действует до ближайших 07:00, затем его заменит курс с сайта банка. Это удобно, если утром сайт банка не ответил.
- Курсы **сохраняются по дням** (таблица `ExchangeRate`). Каждая сделка пересчитывается по курсам дня оплаты, расход компании и реклама — по курсу своего дня. Поэтому новый курс не меняет отчёты за прошлые даты. История начинается с дня обновления CRM: всё, что было раньше, считается по курсу этого дня. Сделка хранится в той валюте, в которой была оформлена.
- Если ни один источник не ответил или вёрстка сайтов изменилась, остаётся последний известный курс, а в настройках показывается подробность ошибки. Можно временно переключиться на ручной ввод.

> Разбор страниц проверен тестами на типовых вариантах вёрстки (таблицы, карточки, JSON). Сайты банка и агрегаторов могут поменять разметку. Если курс перестанет обновляться, проверьте предупреждение в настройках и при необходимости поменяйте источники в `IPAK_RATE_URLS`.

## Роли и права

| | Администратор | Менеджер |
|---|---|---|
| Лиды | все | свои и нераспределённые (кроме созданных администратором) |
| Взять нераспределённый лид | ✓ | ✓ (становится ответственным) |
| Назначить менеджера, массовое назначение | ✓ | — |
| Клиенты | все | те, с кем работал |
| Отчёты | по всем, с фильтром по менеджеру | только по себе |
| Закрыть лид как «Продано» (сделка) | ✓ | ✓ (указывает только сумму продажи) |
| Себестоимость сделки | ✓ | — |
| Изменение и удаление сделок | ✓ | — |
| Раздел «Финансы»: прибыль по лидам, расходы компании | ✓ | — (раздел не виден) |
| Настройки, интеграция, пользователи | ✓ | — |

**Распределение новых лидов** (Настройки → Общие):
- **Вручную.** Лиды приходят нераспределёнными. Администратор назначает их, а менеджеры могут забрать лид кнопкой «Взять».
- **Отказы** вынесены в отдельную вкладку «Отказы» над таблицей лидов, во вкладке «Лиды» их нет. Поиск по имени или телефону и выбор статуса ищут по всем лидам, включая отказы.
- **Страна визы.** Если выбран тип услуги «Визовая поддержка», направление выбирается из списка: Сингапур, Таиланд, Вьетнам, Саудовская Аравия, Кыргызстан. При выборе «Другое» появляется поле для страны. Список задаётся `VISA_COUNTRIES` в `src/lib/constants.ts`. Там же указывается **количество заявлений**.
- **Отчёт «Визы»** (Отчёты → Визы): сколько заявлений на визу продано и по каким странам. Показывает заявления, долю, продажи, выручку и прибыль. Продажа — лид «Визовая поддержка» со сделкой, оплаченной в периоде. Если количество не указано, лид считается за одно заявление, и отчёт об этом предупреждает.
- **Постоянный клиент.** Если у клиента от 3 сделок (любых услуг), его лиды помечаются звездой «Постоянный клиент»: в списке лидов, на канбане, в карточке лида и на странице клиента. Порог задаётся `REGULAR_CLIENT_MIN_DEALS` в `src/lib/constants.ts`.
- Лиды из Meta и лиды, созданные менеджерами, видны всем менеджерам сразу. Лид, который администратор создал вручную без ответственного, менеджеры не видят, пока администратор не назначит ответственного.
- **По очереди (round-robin).** Новый лид получает активный менеджер, которому дольше всех не назначали лидов. Повторное обращение клиента уходит менеджеру, который вёл его раньше.

Права проверяются на сервере в каждом действии, а не только в интерфейсе.

### Раздел «Финансы» (только администратор)

- **Прибыль по лидам.** Сделки, оплаченные в выбранном периоде, сгруппированы по лидам. По каждому лиду видно выручку, себестоимость, прибыль и маржу. Строку можно раскрыть: там сделки лида, а сумму и себестоимость каждой можно изменить. Изменение записывается в историю лида.
- **Раздел «Реклама»** (только администратор). Плитки со сравнением с прошлым периодом: расход, лиды из рекламы, цена лида, цена продажи, продажи, конверсия, цена клика, ROI. Графики расхода и цены лида и таблица «Цена лида по периодам» по дням, неделям или месяцам. Ниже таблица по кампаниям, группам объявлений, объявлениям и формам. Расход пересчитывается по курсу покупки $ своего дня.
- **Ждут себестоимость.** Когда менеджер закрывает лид как «Продано», он указывает только услугу, сумму продажи, валюту и дату оплаты. Сделка попадает в этот блок вверху раздела, а у пункта меню «Финансы» загорается счётчик. Пока есть такие сделки, вверху каждой страницы у администратора видна тонкая строка-напоминание «Продаж без себестоимости: N» со ссылкой на «Финансы». Администратор вводит себестоимость и видит прибыль. Пока себестоимость не указана, сделка помечена «недоделано: нет себестоимости», и прибыль по ней равна выручке.
- **Расходы компании.** Аренда, зарплаты, налоги и любые другие статьи: дата, статья, сумма (в сумах или долларах) и комментарий. Расходы можно изменять и удалять, справа показаны итоги по статьям.
- **Расходы компании.** Статью можно выбрать быстрыми кнопками: такси, еда, коммунальные платежи, аренда, зарплата, налоги, реклама, прочее. Можно и вписать свою.
- **«Взял себе из кассы».** Отдельный тип записи для денег, которые владелец берёт из кассы. Это не расход компании: из чистой прибыли он не вычитается и показывается отдельной плиткой «Взял себе». Рядом плитка «Осталось в компании» = чистая прибыль − взятое себе.
- **Итоги периода:** выручка, себестоимость, валовая прибыль, реклама (расход из Meta), расходы компании и **чистая прибыль**. Чистая прибыль = валовая прибыль − реклама − расходы компании. Выручка пересчитывается по курсу продажи $, себестоимость, реклама и расходы — по курсу покупки $. При фильтре по менеджеру реклама и расходы компании не вычитаются, потому что они общие для всей компании.

## Тесты

```bash
npm test          # Vitest
npm run typecheck # TypeScript
npm run lint      # ESLint
```

Что покрыто тестами:
- разбор лидов Meta (`field_data`, подписи вопросов, узбекские и русские ключи, даты, `created_time`);
- клиент Graph API (пагинация, ошибки токена и прав);
- подпись вебхука `X-Hub-Signature-256`;
- нормализация телефонов в формат `+998XXXXXXXXX`;
- прибыль, пересчёт валют, итоги по сделкам;
- отчёты: KPI и сравнение периодов, воронка, причины отказов и разбивки, реклама (конверсия, цена лида, цена продажи, ROI), менеджеры (время реакции), ряды по дням и неделям;
- round-robin;
- напоминание о повторном звонке (окно 10 минут, отсчёт) и расписание курса (07:00 по Ташкенту);
- разбор курса Ипак Йули Банка из HTML и JSON;
- словари переводов: одинаковые ключи и подстановки во всех языках, нет кириллицы в узбекском и английском.

## Резервные копии и обновление

Ежедневная копия базы (добавьте в `crontab -e` на сервере):

```bash
0 3 * * * cd /home/ubuntu/orient-crm/crm && docker compose exec -T db pg_dump -U crm crm | gzip > /home/ubuntu/backups/crm-$(date +\%F).sql.gz
```

Обновление приложения:

```bash
git pull
docker compose --profile https up -d --build   # миграции применятся автоматически
```

### Автообновление после мерджа

Workflow `.github/workflows/crm-deploy.yml` после каждого пуша в рабочую ветку (`claude/determined-ritchie-kij49y`) подключается к серверу по SSH и запускает `~/orient-deploy.sh` (`git pull` + `docker compose --profile https up -d --build`), затем проверяет, что `https://crm.orienttravel.uz/login` отвечает. Его можно запустить и вручную: **Actions → CRM Deploy → Run workflow**.

Настройка выполняется один раз. На сервере:

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/github_deploy -C github-deploy
printf '#!/bin/sh\nset -e\ncd ~/orient\ngit pull --ff-only\ncd crm\ndocker compose --profile https up -d --build\ndocker image prune -f\n' > ~/orient-deploy.sh && chmod +x ~/orient-deploy.sh
echo "command=\"$HOME/orient-deploy.sh\",no-port-forwarding,no-agent-forwarding,no-X11-forwarding,no-pty $(cat ~/.ssh/github_deploy.pub)" >> ~/.ssh/authorized_keys
```

Ключ ограничен командой `command=…`: с ним можно только запустить обновление, войти в консоль или выполнить что-то другое нельзя.

В GitHub откройте **Settings → Secrets and variables → Actions** и добавьте два секрета:

- `DEPLOY_HOST` — IP сервера;
- `DEPLOY_SSH_KEY` — содержимое `~/.ssh/github_deploy` (закрытый ключ).

Пока секреты не заданы, workflow пропускает обновление с предупреждением.

> **Храните `ENCRYPTION_KEY` в надёжном месте.** Без него сохранённые токены Meta не расшифровать, и их придётся вводить заново.
